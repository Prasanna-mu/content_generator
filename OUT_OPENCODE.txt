Sprint 1 complete. Here's the project structure:
Content Generator/
├── core/
│   ├── llm/
│   │   ├── base.py              # Abstract LLM provider
│   │   ├── factory.py           # Provider factory
│   │   └── providers/ollama.py  # Ollama implementation (qwen2.5:3b)
│   ├── models/schemas.py        # Pydantic models (UserInput, Lesson, Subtopic, etc.)
│   ├── planning/
│   │   ├── prompt_analyzer.py   # Analyzes topic domain/complexity
│   │   ├── lesson_generator.py  # Creates lesson structure
│   │   └── subtopic_generator.py # Generates subtopics with char estimates
│   ├── generation/content_generator.py  # Content + quiz + question bank
│   ├── output/writer.py         # Writes folder structure (.txt, .csv, .json)
│   └── pipeline/orchestrator.py # Coordinates all stages
├── userinput.py                 # CLI input + JSON save/load
├── main.py                      # Entry point with args
├── requirements.txt
├── .env.example
└── README.md
Usage:
# Interactive mode
python main.py

# With saved config
python main.py -i output/my_topic/user_input.json

# Custom model/URL
python main.py -m qwen2.5:3b -u http://localhost:11434
Output structure:
output/your_prompt/
├── user_input.json
├── generation_summary.json
├── lesson_1/
│   ├── lesson_summary.json
│   ├── quiz.csv
│   ├── question_bank.csv
│   ├── subtopic_1/content.txt
│   └── subtopic_2/content.txt
└── lesson_2/...
Prerequisites: Install Ollama, run ollama serve, pull qwen2.5:3b, then pip install -r requirements.txt.

Sprint 2 web search implementation is complete. Here's a summary of what was added:
Changes Made
1. User Input Schema (core/models/schemas.py)
- Added web_search_needed: bool field to UserInput
- Added WebSearchResult and WebSearchReport models
2. User Input Prompt (userinput.py)
- Added prompt: "Enable web search for content enrichment? (y/n): "
3. Web Search Module (core/websearch/)
File	Purpose
query_generator.py	Generates multiple search queries from user prompt using LLM
searcher.py	Parallel web search (DuckDuckGo/Serper/Bing) with worker count from .env
reputation_checker.py	Checks site legitimacy with domain scoring
crawler.py	Parallel HTML fetching for reputable sites
extractor.py	Extracts main content, removes ads/nav/scripts
normalizer.py	Cleans and deduplicates content
analyzer.py	LLM-based content analysis and fact verification
manager.py	Orchestrates the full pipeline
4. Pipeline Integration (core/pipeline/orchestrator.py)
- Web search runs before lesson generation (step 2 of 6 when enabled)
- Results fed to LLM for enriched content generation
- Graceful silent exit if no internet
5. Output (core/output/writer.py)
- Creates references.txt with:
- All search queries used
- Reputable sources with URLs, reputation scores
- Normalized content excerpts
- Analysis summaries
6. Configuration (.env, requirements.txt)
- Added web search config: SEARCH_ENGINE, SEARCH_TIMEOUT, RESULTS_PER_QUERY, MAX_SEARCH_QUERIES, MAX_CONTENT_CHARS
- Added beautifulsoup4 dependency
Key Features
- Parallel processing respects WORKER_COUNT from .env
- Multiple search queries generated from user prompt
- Reputation filtering only uses credible sources
- Silent fallback when internet unavailable
- References report saved as references.txt
